# 06 · MVP 范围共识书（冻结版）

> 状态：✅ 已与需求方达成共识（2026-08）
> 用途：PRD 的前置依据。范围在此冻结，后续需求一律进 backlog。

## 核心原则

> 只做一个最小可演示的 MVP，且达到上线部署条件。在「最小可用」和「可上线」之间取平衡，每一分开发投入服务于最终交付目标。

## MVP 目标定义

**用最小功能集证明核心价值：「10 分钟掌握一个领域一周的进展」——输入主题，看到结构化论文情报，能追问并溯源。**

交付物 = 一个可部署、可演示、可被面试官 5 分钟上手的产品。

## 功能范围冻结表

| 功能 | 进 MVP | 验收标准 |
|---|---|---|
| 领域雷达（趋势图 + 高频关键词） | ✅ | 陌生主题 5 分钟内出图 |
| 结构化摘要（问题/方法/结论/创新点 + 中文） | ✅ | 摘要准确、可读 |
| 深度问答（强制引用溯源） | ✅ | 20 个测试问题溯源率 100%，无来源不回答 |
| 相关文献推荐 | ✅ | 推荐结果与主题相关 |
| 收藏 / 笔记 | ❌ | 与核心价值无关，砍掉 |
| 用户注册 / 多用户 | ❌ | 单用户自用 + 演示模式 |
| 导出 BibTeX | ❌ | 后置 |
| 全文 PDF 解析 | ❌ | 摘要级起步，后置升级 |
| **每日推送（AI Feeds）** | ❌ | **v1.1 后置**（已拍板：核心四功能先上线，最快落地） |

## 上线标准（部署条件）

| 维度 | 标准 |
|---|---|
| 部署环境 | GitHub 仓库 + Streamlit Community Cloud，公网 URL 可访问，push 即部署 |
| 密钥管理 | DEEPSEEK_API_KEY 走 Streamlit Secrets，代码不出现明文 key |
| 启动流程 | 一键启动（文档化），冷启动 ≤ 60 秒 |
| 数据持久化 | 论文库/向量库落盘，重启不丢 |
| 稳定性 | 连续运行 24h 不崩；arXiv 限流有重试和缓存 |
| 成本 | 月运行成本 ≤ ¥10 |
| 演示鲁棒性 | 断网/限流时有无损降级（缓存兜底），演示不翻车 |
| 文档 | README（部署步骤 + 使用说明 + 架构图） |

## 防范围蔓延条款

1. 任何「顺手加个 X」的需求，一律进 backlog 不进本轮，除非能证明它影响核心价值演示或上线
2. 验收以「可演示价值闭环」为准，不以功能数量为准
3. 时间盒：核心开发 ≤ 3 周，到点冻结功能，只修 bug 不增需求

## 决策记录

| 决策点 | 决定 | 理由 |
|---|---|---|
| 部署目标 | GitHub 仓库 + Streamlit Community Cloud | 零成本、push 即部署、满足可上线标准（GitHub Pages 只能跑静态文件，不行） |
| 每日推送 | 不进 MVP，v1.1 后置 | 引入外部推送渠道会拖慢上线；核心四功能已能证明价值 |
| 技术栈 | 本地 embedding + deepseek + ChromaDB | 成本红线内；模型走 ModelScope 下载（hf 源不可达） |
