## 2. 背景与目标

### 2.1 背景

- AI 方向研究者/工程师/PM 需要持续追踪领域进展，但 arXiv 每日新增论文量大，人工筛选每周耗时 2~4 小时（用户研究已验证，见 [[03-用户研究-虚拟访谈纪要]]）
- 竞品均为「搜索逻辑」（查一次即走），无人做好「个人领域追踪」——这是市场缺口（Consensus 用户亲口验证）
- 技术可行性已被开源标杆 paper-qa 验证（引用溯源 RAG 成熟）

### 2.2 产品目标

> **一句话价值主张：给时间稀缺的领域追踪者，一个每天自动更新的情报雷达，让他们 10 分钟掌握一个领域一周的进展。**

### 2.3 成功指标（MVP 阶段可量化）

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 引用溯源率 | 100%（20 问测试集） | 预置评测集逐问核验 |
| 陌生主题出图时间 | ≤ 5 分钟 | 用户操作计时 |
| 月运行成本 | ≤ ¥10 | 账单核算 |
| 稳定性 | 24h 连续运行不崩溃 | 运行监测 |

## 3. 用户画像与使用场景

### 3.1 目标人群（三层）

| 层级 | 画像 | 核心诉求 |
|---|---|---|
| 核心用户 | AI 方向研究生、工程师、研究员 | 持续追踪领域，不遗漏关键论文 |
| 延伸用户 | AI 产品经理、技术投资人、企业决策者 | 快速掌握技术趋势，判断方向 |
| 场景用户 | 转行者、求职者 | 面试/入职前快速建立领域认知 |

### 3.2 典型使用场景

1. **每周追踪**：周一输入关注主题 → 看本周领域雷达 → 读结构化摘要 → 追问细节
2. **开题/综述**：输入新领域 → 5 分钟出领域概览 → 筛选核心文献
3. **速成认知**：面试前输入目标方向 → 快速掌握关键论文与脉络

## 5. 功能需求（MVP 范围）

### FR-1 领域雷达

- **用户故事**：作为领域追踪者，我输入一个研究主题，希望看到该领域近期的论文数量趋势和关键词分布，以便快速判断领域冷热。
- **需求描述**：
  1. 用户输入研究主题（关键词，支持英文为主）
  2. 系统调用 arXiv API 拉取近 30 天相关论文
  3. 展示论文数量随时间趋势图
  4. 展示高频关键词分布
- **验收标准**：
  - [ ] 陌生主题从输入到出图 ≤ 5 分钟
  - [ ] 趋势图数据与 arXiv 实际返回一致（抽样核对 ≥ 5 篇）
  - [ ] arXiv 限流时有重试与缓存，不白屏

### FR-2 结构化摘要

- **用户故事**：作为研究者，我希望每篇论文自动生成「问题/方法/结论/创新点」四段式摘要并翻译成中文，以便快速判断是否值得精读。
- **需求描述**：
  1. 对领域内论文生成结构化摘要
  2. 摘要字段：问题、方法、结论、创新点
  3. 自动中文翻译
  4. 展示原始 arXiv 标题与链接（可跳转）
- **验收标准**：
  - [ ] 摘要四字段完整，无缺漏
  - [ ] 摘要可读性抽查：抽取 10 篇人工判断准确性 ≥ 8/10
  - [ ] 中文翻译无明显错误（人工抽查 10 篇）

### FR-3 深度问答（引用溯源）

- **用户故事**：作为研究者，我想对论文库提问并得到带来源引用的回答，以便快速定位关键信息且可信。
- **需求描述**：
  1. 用户对已入库论文提问
  2. RAG 检索相关段落 → LLM 生成回答
  3. **强制引用溯源**：每个关键回答必须附来源论文（arXiv ID + 链接）；无来源信息不回答
  4. 回答可溯源到具体论文
- **验收标准**：
  - [ ] 20 问测试集引用溯源率 100%
  - [ ] 回答中每条核心结论都有来源标注
  - [ ] 无检索结果时明确提示「库中无相关论文」，不编造

### FR-4 相关文献推荐

- **用户故事**：作为研究者，我看到一篇感兴趣的论文时，希望获得相关文献推荐，以便扩展阅读。
- **需求描述**：
  1. 基于论文向量相似度推荐相关文献
  2. 展示推荐理由（相似度/主题）
- **验收标准**：
  - [ ] 推荐结果与目标论文主题相关（人工判断 ≥ 8/10）
  - [ ] 每次推荐 3~5 篇

### 后置功能（v1.1，明确不进 MVP）

| 功能 | 原因 |
|---|---|
| 每日推送 AI Feeds | 引入外部渠道依赖，拖慢上线（已拍板后置） |
| 收藏/笔记 | 与核心价值无关 |
| 用户注册/多用户 | MVP 单用户自用 + 演示 |
| 全文 PDF 解析 | 摘要级起步，后置升级 |

## 7. 数据需求

### 7.1 数据源

| 数据源 | 用途 | 接入方式 |
|---|---|---|
| arXiv API | 论文元数据（标题/摘要/作者/链接） | 免费 HTTP API，无 key |
| ModelScope | 本地 embedding 模型（bge-small 等） | 模型下载（hf 源不可达，已实测替代方案） |
| deepseek API | LLM 生成摘要/问答 | 已有 key |

### 7.2 数据模型

- 论文（Paper）：title / abstract / authors / arxiv_id / url / published / categories
- 文本块（Chunk）：paper_id / content / embedding（向量）
- 存储：ChromaDB 本地落盘

### 7.3 缓存策略

- arXiv 拉取结果缓存（避免重复请求触发限流）
- LLM 摘要结果缓存（同篇论文不重复生成）

## 9. 里程碑与排期（时间盒 3 周）

| 里程碑 | 内容 | 交付物 | 验收 |
|---|---|---|---|
| **M1（W1）** | 项目骨架 + 数据管道 | arxiv_fetcher + embedder + 本地向量库 | 输入主题 → 50 篇入库可查询 |
| **M2（W2）** | 核心三功能 | 领域雷达 + 结构化摘要 + 前端 | 5 分钟出图 + 摘要可读 |
| **M3（W3）** | 问答 + 部署 + 测试 | 深度问答 + Streamlit Cloud 上线 + 评测 | 溯源率 100% + 公网可访问 |

**冻结条款**：M3 结束功能冻结，只修 bug 不增需求；新需求进 backlog。

## 10. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 检索质量不达标 | 中 | 高 | LitQA 风格评测集量化，调 chunk/embedding/top-k |
| embedding 下载失败 | 低 | 高 | ModelScope 替代源已确认可达 |
| arXiv 限流 | 中 | 中 | 缓存 + 重试 + 批量拉取节流 |
| 部署不稳定 | 低 | 中 | Streamlit Cloud 免费层 + 缓存兜底 |
| 成本超支 | 低 | 低 | deepseek 便宜 + 本地 embedding，月 ¥3~6 |

## 11. 附录：术语表

| 术语 | 含义 |
|---|---|
| RAG | 检索增强生成，先检索资料再生成回答，减少幻觉 |
| Embedding | 文本向量化，把语义转成数字向量用于相似度检索 |
| Chunk | 文本分块，长文切成小块便于检索 |
| 引用溯源 | 回答必须附来源，无来源不回答（防编造） |
| ChromaDB | 本地向量数据库 |
| Streamlit | Python 快速搭建 Web 界面的框架 |
